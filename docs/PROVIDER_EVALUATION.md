## Прототип для проверки (рекомендация ТЗ)

1 маршрут (TLV → Италия), 9 комбинаций дат, все аэропорты страны:

Скрипт `probe` прогоняет один и тот же план **по каждому поставщику с ключом отдельно**,
без резервирования и дозаполнения, и пишет отчёт сравнения:

```bash
npm run probe -w apps/api                          # холостой прогон: план и бюджет
npm run probe -w apps/api -- --yes                 # по 1 запросу на каждый сервис (по умолчанию)
npm run probe -w apps/api -- --requests 4 --yes    # по 4 запроса на сервис
npm run probe -w apps/api -- --live ignav,serpapi --dep 2027-05-10 --ret 2027-05-20 --yes
```

- **Без `--yes`** ничего не запрашивается: скрипт показывает, на что уйдёт каждый запрос.
- **Бюджет — `--requests N` на каждый сервис, по умолчанию 1.** Лимит соблюдается дважды:
  вызовы планируются под бюджет, а запрос сверх лимита блокируется до отправки.
- **При 1 запросе:**
  - Travelpayouts — FCO и средняя пара дат;
  - Ignav, Duffel — одна полная проверка туда-обратно;
  - SerpApi, HasData — только страница рейсов туда: настоящие рейсы и цена туда-обратно, но
    рейсы обратно требуют второго запроса. В отчёте помечено _outbound only_;
  - если сервис нужен на обоих этапах (Ignav), его запрос идёт на проверку цен.
- **Цели проверки одинаковые для всех live-поставщиков:** самые дешёвые маршруты по
  предварительным ценам, затем FCO, MXP, VCE, NAP, BGY.
- **Отчёт** пишется в `apps/api/probe-reports/*.md` и `*.json` (папка в `.gitignore`). В нём:
  - запросы, сбои и время по каждому поставщику;
  - **покрытие перевозчиков**: El Al (LY), Arkia (IZ), Israir (6H), Wizz, Ryanair, easyJet,
    Vueling, Volotea;
  - самая дешёвая цена по каждому маршруту у каждого поставщика и разброс между ними.

Если перевозчика нет в отчёте, это ещё не значит, что источник его не видит: на эти даты он мог
просто не оказаться в числе подходящих вариантов. Для уверенности прогоните несколько дат.

Метрики для оценки: число вызовов API на мониторинг (`SearchRun.combinationsChecked`),
доля кэш-попаданий (`DailyBatch.cacheHits`), расхождение indicative vs live цен,
доля пропущенных indicative-кэшем комбинаций.

## Оценка объёма запросов

500 пользователей × 3 направления × 9 комбинаций × ~10 аэропортов ≈ 135 000 indicative-ключей в день
(до дедупликации), но live-проверок — только top-N (по умолчанию 10 + по одной на аэропорт) на мониторинг.
Параметры: `LIVE_CHECK_TOP_N`, `PROVIDER_CONCURRENCY`, `SEARCH_CACHE_TTL_MINUTES`.
